# Security Policy

The cwserver project takes security seriously. We appreciate responsible security researchers and community members who help us identify and resolve vulnerabilities.

## Supported Versions

Security updates are provided for actively maintained release versions.

| Version | Supported |
| ------- | --------- |
| 4.1.x   | :white_check_mark: |
| 4.0.x   | :white_check_mark: |
| < 4.0   | :x: |

Only the versions listed above are eligible for security updates. Users are encouraged to upgrade to the latest supported release.

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues, discussions, or pull requests.**

If you discover a potential security vulnerability in cwserver, please report it privately through one of the following channels:

- **GitHub Security Advisories:** [Report a vulnerability](https://github.com/fsystech/cwserver/security/advisories/new)
- **Email:** Contact the project maintainers through an officially published security contact.

When reporting a vulnerability, please include:

- A clear description of the vulnerability.
- The affected cwserver version.
- The affected component or functionality.
- Steps to reproduce the issue.
- Potential security impact.
- A proof of concept or relevant code, if available.

Please avoid including sensitive user data or production credentials in your report.

## Response and Disclosure Process

The project maintainers aim to follow this process:

1. **Acknowledgment:** We aim to acknowledge a vulnerability report within 3 business days.
2. **Assessment:** The maintainers will investigate and determine the severity, impact, and affected versions.
3. **Resolution:** If the vulnerability is confirmed, we will work on an appropriate fix and determine which supported versions require updates.
4. **Communication:** The reporter will receive updates during the investigation and remediation process.
5. **Disclosure:** Once a fix is available, the maintainers may publish a security advisory with relevant details and upgrade recommendations.

If a report is determined not to be a security vulnerability, the reporter will be informed with an explanation where appropriate.

## Responsible Disclosure

We request that security researchers:

- Allow reasonable time for the maintainers to investigate and address reported vulnerabilities.
- Avoid publicly disclosing vulnerability details before a fix or coordinated disclosure.
- Do not exploit vulnerabilities beyond what is necessary to demonstrate the issue.
- Do not access, modify, or expose other users' data.
- Act in good faith and respect the privacy and security of project users.

We appreciate responsible disclosure and the effort required to improve the security of cwserver.

## Security Updates

Security fixes will be communicated through GitHub Security Advisories and project release notes when appropriate.

Users should regularly update to the latest supported release to receive security improvements.
